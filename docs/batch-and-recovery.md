# 批次提交与恢复

在同一个 Windows 本地卷上使用同一输出目录、配置、算例、清单和运行环境续算。冻结的 `plan.mat` 保存经过校验的工况和实验请求，`plan.json` 提供 Python 可读的配置、设置、版本和清单。新场景的 `metadata.json` 指向两份计划并记录其 SHA-256。归档时保留这两个计划文件与场景的相对位置。

同一时间仅一个进程可持有 `.writer.lock` 的操作系统锁。锁文件可长期存在。进程退出后操作系统释放锁，恢复无需删除锁文件。每个场景在 `.staging` 中写完六个交换文件及 `checksums.json`，之后通过同盘原子改名发布。正式名称每场景只能发布一次。没有终态的场景也有六个交换文件，其中图 CSV 只有表头。

| 状态 | 恢复方式 |
| --- | --- |
| 正常退出或已发布后中断 | 使用相同输入重跑。逐一核对现有场景的六份文件和计划引用，跳过完好场景并重建结果汇总。 |
| 场景运行或暂存中断 | 同一批次重跑缺失的正式场景。恢复只读取正式目录，暂存残留单独保留。确认无 writer 后可移动或清理 `.staging` 中的废弃产物。 |
| 正式目录文件缺失、损坏或清单缺失 | 中止续算。用已验证备份恢复原始字节，或保留问题目录并使用新批次重跑对应输入。 |
| 配置、源码、环境或算例有变 | 开新目录。已有 schema 1 数据继续使用 Python 读取。复现旧批次时匹配产生该计划的版本与路径。 |
| 文件系统或发布错误 | 批次停止并报告错误，已发布场景保留。处理磁盘或路径问题后用同一计划续算。 |
| 多进程竞争 | 第二个 writer 会收到 `ACCFMLab:BatchLock`。等前一进程结束后再执行。 |

输入错误、递归上限、求解调用异常和账本审阅通过 `metadata.error_category` 区分。上游返回失败但随后恢复的求解保留在事件和 `has_solver_failure` 中。模型返回 OPF 相关停岛时用 `model_opf_trip` 标识。未知程序错误立即抛出，继续执行前需诊断；此前场景有效。无终态错误场景会独立提交；重试这类场景时以新目录创建新批次。

使用以下命令检查发布字节、来源和语义。复制单场景可校验其六个文件。完整来源校验需要训练或归档目录中的计划文件。

```powershell
python python/read_run.py --require-plan runs/example-batch/scenario_000003
```

原子改名及进程退出已在本地 NTFS 验证。物理掉电、实际磁盘用完、网络文件系统和进程卡死自动终止仍待验证。

关键依赖清单记录实际解析到的 MATPOWER 相对路径和 SHA-256，涵盖 PF/OPF、岛提取、内外索引、负荷转换和电气方程。它可检测被跟踪函数的改动及路径遮蔽。相同计划还比较平台源码及算例摘要。MATLAB 内核、未列出的 MATPOWER 传递依赖、BLAS 和自定义函数需要依靠相同部署与固定回归重现。
